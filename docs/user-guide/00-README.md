# IE Central — User Guide

Welcome to **IE Central**, the internal platform for Import-Export Tire. This is your everyday
hub for clocking in, requesting time off, viewing pay stubs, sending messages, running reports,
filling out safety checklists, finding documents, and dozens of other day-to-day tasks.

This guide is written for **everyone who uses IE Central** — from a warehouse associate clocking
in on a scanner to a manager approving timesheets or running a sales report. You don't need any
technical background to use it.

> Looking for how the system is *built* (databases, AWS, code)? That lives in the
> [technical documentation](../iecentral/00-README.md), not here.

---

The guide is split into six sections. Find the one that matches what you're trying to do:

| Section | Use it when you want to… |
|---|---|
| [1 — Getting Started](01-getting-started.md) | Log in, find your way around, search, change your password, set up your profile, manage notifications |

(see Section 1) to jump straight to a screen.

## What you can see depends on your role

IE Central shows different menus and screens to different people. A warehouse associate, an office
manager, and a system administrator each see a different set of options in the sidebar. Throughout
this guide, when a feature is **limited to managers or admins**, it's marked like this:

> 🔒 **Manager / Admin only** — most employees won't see this screen.

If a screen described here isn't in your sidebar, you probably don't have access to it — that's
normal. Ask your manager or an administrator if you think you should.

## Getting help

- Many screens have a **Help** button (often a **?** icon) that opens a help panel explaining that
  specific screen.
- If something looks broken or wrong, contact your manager or the IE Central administrator.
- For anonymous safety or conduct concerns, use
  **[See Something, Say Something](06-operations.md#see-something-say-something)**.

## House style (for guide authors)

*This section is for whoever maintains the guide — readers can skip it.*

Keep every cluster guide consistent:

- **Audience:** a non-technical employee. No code, no file paths, no database/AWS terms. Describe
  what the user *sees and clicks*, not what happens behind the scenes.
- **Voice:** second person ("you"), present tense, plain language. Short sentences. Friendly but
  not chatty.
- **Structure per module:** a short intro ("what this is for / who uses it"), then **numbered
  step-by-step instructions** for the common tasks, then tips/notes/gotchas. Use real button and
  menu labels in **bold** (e.g. click **Clock In**, open the **Time Off** menu).
- **Navigation:** start tasks from the sidebar — "Open **Time Clock** from the sidebar, then…".
- **Permissions:** mark manager/admin-only features with the
  `> 🔒 **Manager / Admin only**` callout shown above.
- **Tables** for status meanings, field references, and option lists. **Numbered lists** for
  procedures. **Bullet lists** for tips.
- **Cross-link** between sections with relative links (e.g. `[pay stubs](02-time-and-pay.md#pay-stubs)`).
- **No screenshots** for now — describe locations in words ("top-right corner", "the green button").
- Each guide opens with an H1 title and a short table of contents of its `##` sections.
- When folding in older standalone guides (e.g. the ATS/Applications guides), preserve their
  useful step detail but rewrite to this style and remove duplication.
